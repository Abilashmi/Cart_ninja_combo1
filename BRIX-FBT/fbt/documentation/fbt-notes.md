## FBT bundle offer, images and spacing

**FBT bundle offer, images and spacing.** FBT → "Bundle offer" (`fbt_widget_settings.offer_enabled / _type (percentage | fixed_amount) / _value / _text`, `{count}` / `{discount}` tags) plus a per-rule choice on Manual saved rules (`fbt_rules.offer_mode` = widget | none | percentage | fixed_amount, `offer_value`; own columns, the old `discount_type` / `discount_value` are unused because their types aren't known on every database; self-healing via `ensureFbtOfferColumns`). Rules in `utils/fbt-offer.shared.js`. It applies when the cart holds the viewed product (one of the rule's trigger products) and every recommended product; one unit of each is discounted by the `extensions/brix-fbt-discount` Function (PRODUCT, trusts only `$app:fbt_offer_config` = `{ sets: [{ id, t, o, k: p|f, v }] }`, 9 KB cap; skips `_brixReward` / `_brix_pack_id` / `_brix_combo_id` lines; fixed amounts split by price, never in another currency; each line in one set, best saving first). "Create the discount" (`fbt_widget_settings.offer_create_discount`, self-healing, default 1; `offer.createDiscount`): unticked = show only, for stores with their own automatic discount: the Function config is written with no sets (BRIX's discount gives nothing, none is created), state `show_only`, and the widget shows the offer on every rule that has one (`buildFbtOfferConfig(..., { maxBytes: Infinity })`, no 9 KB limit; with the discount on, a store with ~140+ rules gets offers on only the first ~63, e.g. knitnknot). "Offer from this many items" (`offer_min_items`, show only, 0 = the whole set): the condition offer gets `min`, the widget offers it on any shown products (size-match spares too) once `min` are picked with the viewed one, savings on the picked ones (`offerSavings` returns `count`); the default text then reads "Buy any {count} together and save {discount}" (`FBT_OFFER_ANY_TEXT_DEFAULT`); scenario 4b of `widget-browser-check.mjs`. `syncFbtOfferDiscount` (`services/fbt-offer-shopify.server.js`, never throws, states like the reward gift, stored in `offer_state / offer_message`) runs on every FBT save and after BrixBar's FBT rule tools; it writes the config, ensures the automatic discount "BRIX Bundle Offer", and only when ACTIVE puts `offer` on those rules' `fbt_widget.condition` entries — the widget shows the offer text only then, only while every product of the set is shown, and with an offer "Add all" also adds the viewed product (the page form's variant, unless already in the cart). Offer text style (FBT → Bundle offer → Offer text style): `offerTextColor / offerBgColor` ('' = price colour / its tint), `offerFontSize` (10-24, default 13), `offerFontWeight` (400-800, default 700), `offerItalic`, `offerAlign`, `offerFontFamily` ('inherit' = theme font, else a Google font the widget loads) in the template JSON (`fbt-style.shared.js` `pickFbtOfferStyle` / `fbtOfferCss`, mirrored by `fbtOfferCss` in `fbt-widget-render.liquid`). Show the discount (FBT → Bundle offer, template JSON `offerShowSavings / offerStrikeTotal / offerProductPrices`, default off): once every product of the set is picked, a "You save ₹X" line, the bundle total (the viewed product included, its price from Liquid `data-product-price`) struck through with the new one, and each product's price after its share; the maths is `fbt-offer.shared.js` `fbtOfferSavings` (one unit each, fixed amounts shared by price), mirrored by the widget's `offerSavings`. Variant picker (Styling → "Variant picker on each product", `showVariantPicker`, default off): a dropdown on products with options (sold-out listed, disabled), from the live `/products.json` / `.js` variants (`withLivePrice` → `product.variants`), the picked one priced, totalled and added. Tests: `fbtOfferSavings` in `tests/fbt-offer/fbt-offer.test.mjs`, scenario 0 of `widget-browser-check.mjs`. **Match the shopper's size** (FBT → Configure → AI-Powered, template JSON `sizeMatch / sizeMatchMissing (hide | note) / sizeMatchOption`; the widget follows `sizeMatchLive`, which the admin saves true only in AI mode): the size picked on the product page (the page product's `.js` via `data-product-handle` + the form's variant, polled every 500 ms since themes change it without events) picks each suggestion's in-stock variant of that size (preselected, priced, added); a suggestion without it is, by `sizeMatchMissing`: `replace` (default) = a spare AI pick in that size takes its place (else a spare with no size option; spares = `fbt_rules.backup_products`, self-healing column, up to 6 per product, saved by Configure AI / Regenerate via `computeAiPairingRules(..., { spares })` and sent as `backupProducts` in the condition; never part of a bundle offer), `hide`, or `note` = greyed "Not in <size>" (never added); the bundle offer drops when a set product is missing; products with no Size / Age / Years option show as usual. Sizes match by number ("12 Years" = "12Y", "11-12 Y" holds 12, years never months, letter sizes as text): `app/utils/fbt-size.shared.js` (tests `tests/fbt-offer/fbt-size.test.mjs`), ES5 copy in `fbt_widget_render.js`, scenario S of `widget-browser-check.mjs`. Loading: the widget's settings (5 min), `/products.json` and `.js` (60 s) are shared per page visit in `window.__brixFbtCache` (`cachedJson`), because Dawn-style themes re-render the product section on every size click and re-create the widget; it then draws again before the next paint instead of hiding and re-downloading. The Add button's variant lookup stays uncached (fresh stock). First load shows `renderSkeleton` placeholders in place; redraws keep the widget's height. Scenario L of `widget-browser-check.mjs`. Widget images / spacing: `imageSize / imageFit / imageRadius / imageBg / cardWidth / gap / cardPadding / widgetPadding / marginTop / marginBottom` in the template JSON (`utils/fbt-style.shared.js` `pickFbtLayout`, mirrored by `fbtNum` in `fbt-widget-render.liquid`; defaults = the old fixed sizes; list rows use 75% of the image size, phones 70% of the widget padding). Inside each product: `imageTextGap` (0-40) / `textGap` (0-24), null = the old 8 / 4 px on cards, 12 / 2 px on list rows (`fbtLayoutSizes`), `rowGap` (0-40, default 0) between list rows. Image popup (`imagePopup`, default on, Styling → "Open pictures on image tap"): a tap on a product's image opens `openFbtGallery` in `fbt_widget_render.js` (the card picture at once, then every picture from `/products/<handle>.js` via `cachedJson`, deduped by file name; arrows / swipe / ← →, thumbnails, price, "View full details"; Esc / backdrop closes; phones = bottom sheet); the admin preview shows a one-picture version (`.fbtpv-zoom`). Scenarios 9-10 of `widget-browser-check.mjs`. Tests: `tests/fbt-offer/*.test.mjs` (shared rules, Function logic, sync with fakes), `node tests/fbt-offer/widget-browser-check.mjs`, FBT admin checks in `tests/pairing/assistant-browser-check.mjs`. Needs `npm run deploy` for the Function; never claim the offer applies at checkout until seen on a dev store order.

## Pairing Assistant (FBT + cart upsells)

**Pairing Assistant (FBT + cart upsells).** FBT → Configure → Manual ("Describe in words" / "From past orders" next to "Pick products") and the Cart Editor's Upsell manual rules (two buttons → modal) share `components/shared/PairingAssistant.jsx`, backed by `api.pairing-assistant.jsx` (read-only: it suggests, the page adds the picked rules to its own manual rules, and the normal Save publishes them, so the storefront is unchanged). *From past orders* = `pairing-assistant.server.js` `loadOrderPairs`: recent Shopify orders (`read_orders` = last 60 days, paged, 25 s budget) merged by order id with older webhook-recorded `store_order_line_items`, test/cancelled skipped, 5 min cache; archived/deleted products shown but can't be added. *Describe in words* (1 AI credit, only when the model is called) = the model returns a plan (`products / collections / productTypes / tags / allProducts / fromOrderHistory`) and `utils/pairing.shared.js` `buildRulesFromPlan` matches every name to the real active catalog (never invents a product; unknown names come back as warnings; "what customers buy with X" = one rule per product from past orders); no model or a failed call → `parsePromptHeuristically` ("A with B", "A -> B"). Group words that aren't in product titles ("tops", "bottoms") resolve through collections, product types, tags, then `CATEGORY_WORDS` (`matchGroup`); "match / pair A and B" makes rules both ways. Rule keys (`fbtRuleKey` / `upsellRuleKey`) stop duplicates. FBT **AI-Powered** mode also has an optional instructions box (`fbt_widget_settings.ai_instructions`, self-healing): on Configure AI / Regenerate, `resolveFbtInstructions` turns it into rules (cached with a hash in `ai_instruction_rules`, so unchanged text costs no new credit) and `generateAiFbtRules(..., { pinned })` → `mergeInstructionRules` puts them first on the products they name ("every product" offers on all), AI picks fill each product up to the count. Tests: `node --import ./tests/packs/register.mjs --test tests/pairing/*.test.mjs`, `node tests/pairing/assistant-browser-check.mjs` (Vite harness, real FBT page + Upsell section). Not yet tried on a real store's orders or model.
